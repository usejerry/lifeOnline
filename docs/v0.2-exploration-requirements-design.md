# 人生支线 V0.2「增加探索感」需求拆解

> 前端：nestjs-h5；后端：nestjs-demo  
> 本文先完成需求、交互、数据库和接口设计，不直接实现代码。

## 1. 产品目标

V0.1 已形成基础闭环：

~~~
登录 → 设置偏好 → 推荐支线 → 接受 → 完成 → 纪念卡 → 记录
~~~

V0.2 要增加三个感受：

1. 附近真的有内容：支线与所在城市和附近地点相关。
2. 内容只在此刻出现：天气、距离、隐藏条件和每周主题改变内容。
3. 探索可以积累：支线可以稍后完成，完成后形成城市徽章。

新闭环：

~~~
获取定位
→ 附近地图 + 当前天气 + 本周主题
→ 普通支线 / 隐藏支线
→ 立即接受或加入稍后完成
→ 到达限定地点并完成
→ 增加城市进度和徽章等级
~~~

## 2. 七项需求的具体边界

| 原需求 | V0.2 定义 | 暂不包含 |
|---|---|---|
| 附近支线地图 | Explore 增加地图/列表切换，显示固定地点和附近 POI 支线 | 路线规划、轨迹记录 |
| 地点限定支线 | 接受时锁定目标，完成时校验距离 | 后台持续定位、反 GPS 模拟 |
| 天气限定内容 | 推荐和附近接口按当前天气过滤 | 分钟级气象预警 |
| 隐藏任务 | 进入范围后出现神秘标记，点击后永久发现 | AR、二维码任务 |
| 城市徽章 | 按城市完成数生成 1/3/10 级徽章 | 通用成就系统 |
| 每周主题 | 每周一个主题和一组支线 | 用户自建主题、投票 |
| 收藏与稍后完成 | 支线加入待完成列表，不占进行中名额 | 文件夹、标签、排序 |

## 3. 地图与天气选型

V0.2 建议统一使用高德：

- 前端地图：高德 JS API 2.0。
- 前端定位：AMap.Geolocation。

## 5. 定位交互

### 首次进入

不要直接弹系统权限框，先解释：

~~~
开启附近探索
我们会用你本次的位置寻找附近支线，不会持续记录位置。

[暂不定位] [开启附近探索]
~~~

用户点击后再调用定位。

### 定位成功

只在当前会话内存保存：

~~~ts
interface CurrentLocation {
  longitude: number
  latitude: number
  accuracy: number
  cityName?: string
  adcode?: string
}
~~~

不写 localStorage，然后加载附近支线。

### 定位拒绝或失败

提供重新授权提示和“按城市浏览”。此时仍展示普通列表及每周主题，不展示地点限定和隐藏任务。

### 隐私边界

- 不建立位置轨迹表。
- 不后台持续定位。
- 附近查询只使用请求位置。
- 仅在接受/完成地点支线时保存目标与完成位置快照。

~~~

用户拖动地图时不连续请求。停止后显示“搜索此区域”，点击才重新查询。

## 7. 地点限定支线

三种模式：

~~~ts
enum LocationMode {
  ANYWHERE = 'anywhere',
  FIXED = 'fixed',
  POI_TYPE = 'poi_type',
}
~~~

| 示例 | 模式 | 数据来源 |
|---|---|---|
| 完成一件五分钟小事 | anywhere | 无位置 |
| 去西湖边记录一种声音 | fixed | Quest 固定坐标 |
| 去附近公园散步 | poi_type | 高德附近公园 |

POI 类型任务不保存全国公园：

~~~
用户位置 → quest.poi_type → 高德周边搜索 → 具体候选地点
~~~

同一 Quest 可以在不同城市对应不同公园。

接受时前端只发送 questId 和 poiId。后端根据 poiId 重查 POI，不能相信前端提供的地点名称和坐标，然后把目标快照写入 QuestRecord。

完成时上传当前位置，后端用 Haversine 公式计算：

~~~
distance <= completionRadiusMeters → 完成
distance > completionRadiusMeters  → LOCATION_TOO_FAR
~~~

V0.2 不做路线导航，查看路线直接打开高德 URI/App。

## 8. 天气限定内容

quest.weather_rule 使用 JSON：

~~~json
{
  "include": ["clear", "cloudy"],
  "exclude": ["rain", "snow"],
  "minTemperature": 5,
  "maxTemperature": 35
}
~~~

内部标签固定为 clear、cloudy、rain、snow、windy、hot、cold，由后端转换供应商天气文本。

天气影响推荐、附近候选、探索标签和接受前校验。已经接受后，即使天气变化也允许完成，避免用户出发后无法提交。

天气服务失败时隐藏天气限定任务，普通任务继续返回。天气按 adcode 在进程内缓存 10 分钟，多实例后再换 Redis。

## 9. 隐藏任务

V0.2 隐藏任务只支持 fixed：

~~~
范围外：不可见
进入发现范围：神秘问号，不泄露内容
点击且服务端距离校验成功：展示完整任务，记录 discoveredAt
接受：正常 QuestRecord
完成：计入城市进度
~~~

- unlock_radius_m：发现半径，建议 300～500m。
- completion_radius_m：完成半径，建议 100～300m。

Web 定位无法彻底阻止模拟位置，V0.2 不做反作弊系统。

## 10. 城市徽章

| 完成数 | 等级 | 示例 |
|---:|---|---|
| 1 | discovered | 初见杭州 |
| 3 | explorer | 杭州探索者 |
| 10 | storyteller | 杭州故事家 |

V0.2 不建 badge、user_badge 表，直接聚合：

~~~sql
SELECT city_adcode, city_name, COUNT(*) AS completed_count
FROM quest_record
WHERE user_id = ?
  AND status = 'completed'
  AND city_adcode IS NOT NULL
GROUP BY city_adcode, city_name;
~~~

Profile 展示等级和下一等级进度。数据量变大后再建聚合缓存表。

## 11. 每周主题

规则：

- 同一时间只启用一个主题。
- start_at <= now < end_at 表示有效。
- Quest 通过 weekly_theme_id 属于主题。
- 主题结束后，已接受任务仍可完成。
- Explore 地图使用主题 Marker。
- Today 增加主题卡，Explore 增加“本周”筛选。

V0.2 不做复杂奖励表。

## 12. 收藏与稍后完成

统一文案：

~~~
☆ 稍后完成
★ 已加入
~~~

稍后完成可以很多条且不占进行中名额；接受仍同时只能一条。

从稍后完成列表接受后：

- 清空 saved_at。
- 创建正常 QuestRecord。
- 如果也是已发现隐藏任务，保留 discovered_at。

下架任务继续显示标题，但禁用接受按钮。

## 18. 接口清单

新增：

| 方法 | 路径 | 鉴权 | 用途 |
|---|---|---|---|
| GET | /quests/nearby | 否 | 附近候选、城市、天气 |
| GET | /themes/current | 否 | 当前主题 |
| POST | /quests/:id/discover | 是 | 发现隐藏任务 |
| PUT | /me/quest-library/:id/save | 是 | 加入稍后完成 |
| DELETE | /me/quest-library/:id/save | 是 | 移除 |
| GET | /me/quest-library | 是 | 查询 saved/discovered |
| GET | /me/city-badges | 是 | 城市徽章 |

### Nearby

~~~http
GET /api/v1/quests/nearby
  ?longitude=120.123456
  &latitude=30.123456
  &radius=3000
~~~

响应包含 context.city、context.weather 和 items。普通 item 包含 quest 与具体 target；未发现隐藏 item 的 quest 为 null，只返回神秘标记必要信息。

### 隐藏发现

~~~http
POST /api/v1/quests/:id/discover
Authorization: Bearer token

{
  "longitude": 120.123456,
  "latitude": 30.123456
}
~~~

服务端验证隐藏、启用和发现距离，过远返回 HIDDEN_QUEST_TOO_FAR。

### 支线库

~~~http
PUT    /api/v1/me/quest-library/:questId/save
DELETE /api/v1/me/quest-library/:questId/save
GET    /api/v1/me/quest-library?kind=saved&page=1&pageSize=20
GET    /api/v1/me/quest-library?kind=discovered&page=1&pageSize=20
~~~

PUT 重复调用必须幂等。

### 推荐接口扩展

现有 /quests/recommendation 增加可选 longitude/latitude：

- 有定位：解析城市天气，过滤地点天气规则，可优先主题。
- 无定位：保持 V0.1，只返回无限定任务。

### 接受接口扩展

~~~json
{
  "questId": 15,
  "poiId": "B0FF1234",
  "longitude": 120.123456,
  "latitude": 30.123456
}
~~~

- anywhere：只需 questId。
- fixed：后端读 Quest 坐标。
- poi_type：poiId 必填，后端重查 POI。
- 天气任务：坐标必填，接受前校验天气。
- 隐藏任务：必须已发现。
- 成功后清空 saved_at。

### 完成接口扩展

现有 multipart /quest-records/:id/complete 增加 longitude、latitude。地点任务必填，普通任务可不传。

新增错误码：

| code | HTTP | 说明 |
|---|---:|---|
| LOCATION_REQUIRED | 400 | 缺少完成位置 |
| LOCATION_TOO_FAR | 409 | 距离太远 |
| WEATHER_NOT_MATCHED | 409 | 接受时天气不符 |
| HIDDEN_QUEST_NOT_DISCOVERED | 403 | 尚未发现 |
| MAP_PROVIDER_UNAVAILABLE | 503 | 地图服务不可用 |

## 21. 稳定性和安全

- Nearby 半径限制 1～10km，默认 3km。
- 经纬度验证范围且最多 6 位小数。
- 每次最多 50 个候选。
- 相同 POI 类型去重后再请求。
- 天气按 adcode 缓存 10 分钟。
- JS Key 限制域名。
- Web 服务 Key 不返回前端。
- 高德失败时降级：地图到列表、POI 到 fixed、天气任务隐藏。

## 23. 关键验收

- 定位前解释用途，拒绝仍可浏览。
- POI 名称和目标坐标由后端确认。
- 普通任务不要求完成定位。
- 地点任务超出半径不能完成。
- 天气失败不影响普通任务。
- 已接受任务不因天气变化无法完成。
- 隐藏任务范围外不泄露。
- 发现接口服务端校验距离。
- 重复稍后完成不产生重复行。
- 移除 saved 不删除 discovered。
- 主题结束后已接受任务仍可完成。
- 1/3/10 条产生正确城市徽章。

## 24. 明确不做

- 连续 GPS 轨迹与回放。
- 多地图供应商切换。
- Redis、消息队列。
- 通用徽章配置后台。
- 反定位作弊。
- AR 隐藏任务。
- 推荐算法与曝光埋点。

这些都不是完成本次七项需求闭环的必要条件。
