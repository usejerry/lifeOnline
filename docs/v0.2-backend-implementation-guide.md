# V0.2 探索功能后端实现与学习说明

## 1. 这次到底建几张表

V0.2 **新增 2 张表，修改 2 张旧表**，因此探索业务一共使用 4 张核心表：

| 表                   | 类型 | 作用                                                                           |
| -------------------- | ---- | ------------------------------------------------------------------------------ |
| `quest`              | 修改 | 支线任务模板。标题、规则、地图地点、天气限制、是否隐藏都定义在这里。           |
| `quest_record`       | 修改 | 用户接取记录。保存接取时的目标和规则快照，以及完成时的位置、距离、城市、天气。 |
| `weekly_theme`       | 新增 | 每周主题的文案、封面和生效时间。                                               |
| `user_quest_library` | 新增 | 用户收藏任务、发现隐藏任务的状态。一个用户与一个任务最多一行。                 |

`quest` 是“可运营修改的模板”，`quest_record` 是“用户行为凭证”。两者不能合并：如果运营把任务完成半径从 500 米改成 100 米，用户已经接取的任务仍应按当时的 500 米完成，所以记录表必须保存快照。

城市徽章暂时不建表。它由 `quest_record.completed_city_adcode` 分组统计得到；等以后徽章出现等级、图案、领取奖励等独立生命周期，再单独建表。

## 2. 后端模块职责

```text
LocationModule
├─ AmapProxyController   高德 JS API 安全密钥代理
├─ AmapService           逆地理编码、天气、POI 周边搜索
└─ LocationService       Haversine 距离与天气规则判断

QuestModule              任务列表、推荐、附近地图任务、隐藏任务发现入口
QuestRecordModule        接取、进行中、放弃、带位置校验的完成
ThemeModule              当前周主题
QuestLibraryModule       收藏、发现记录、城市徽章汇总
```

模块这样拆的原因是：距离算法和地图供应商不属于任务表本身；将来若高德换成其他地图，只需替换 `AmapService`，任务记录和业务规则不用跟着重写。

## 3. 高德地图两个 Key 的区别

- **Web 端（JS API）Key**：属于公开标识，前端 `AMapLoader.load({ key })` 使用。
- **安全密钥**：属于机密，只放 NestJS 环境变量 `AMAP_SECURITY_CODE`。前端通过 `serviceHost` 请求本站代理。
- **Web 服务 Key**：是另一种 Key，后端调用逆地理编码、天气和 POI 接口时使用 `AMAP_WEB_SERVICE_KEY`。不能拿 JS API Key 代替。

开发环境写入 `.env.dev`，默认环境写入 `.env`，生产环境写入 `.env.prod`。这三个文件均已被 Git 忽略；正式部署时也可以由部署平台注入同名环境变量。

前端配置方式：

```ts
window._AMapSecurityConfig = {
  serviceHost: '/_AMapService',
};
```

代理只会转发到高德官方固定域名，并强制覆盖客户端传来的 `jscode`，防止浏览器伪造密钥或把接口变成任意地址代理。

## 4. 接口清单

所有业务接口前缀均为 `/api/v1`。

| 方法   | 地址                                                         | 登录 | 用途                                   |
| ------ | ------------------------------------------------------------ | ---- | -------------------------------------- |
| GET    | `/quests/nearby?longitude=120.15&latitude=30.27&radius=5000` | 否   | 返回附近固定地点任务和动态 POI 任务。  |
| GET    | `/themes/current`                                            | 否   | 当前有效周主题，没有时返回 `null`。    |
| POST   | `/quests/:id/discover`                                       | 是   | 靠近后解锁隐藏任务。                   |
| PUT    | `/me/quest-library/:questId/save`                            | 是   | 收藏任务，重复调用仍成功。             |
| DELETE | `/me/quest-library/:questId/save`                            | 是   | 取消收藏，不删除已发现状态。           |
| GET    | `/me/quest-library?kind=saved`                               | 是   | 收藏列表；`kind` 也可为 `discovered`。 |
| GET    | `/me/city-badges`                                            | 是   | 按完成城市汇总徽章。                   |
| POST   | `/quest-records`                                             | 是   | 接取任务，固定地点自动生成目标快照。   |
| POST   | `/quest-records/:id/complete`                                | 是   | 完成任务，表单可带图片、经纬度和文字。 |

### 4.1 附近任务

请求：

```http
GET /api/v1/quests/nearby?longitude=120.1551&latitude=30.2741&radius=5000
```

固定任务直接计算用户到后台坐标的距离。`poi_type` 任务通过高德周边搜索找实际店铺，每个结果会返回 `poiId`、名称、地址、坐标；前端接取时把用户选择的那一个目标提交回来。

如果尚未配置 Web 服务 Key，固定地点任务仍正常返回，`context.mapWebServiceConfigured` 为 `false`，动态 POI、城市与天气暂时降级为空。

### 4.2 接取动态 POI 任务

```json
{
  "questId": 3,
  "poiId": "高德返回的POI ID",
  "targetName": "某某咖啡馆",
  "targetAddress": "某某路 10 号",
  "longitude": 120.16,
  "latitude": 30.27
}
```

固定地点任务仍只需传 `questId`，保持 V0.1 前端兼容。用户接取成功后会自动取消收藏，因为任务已经进入“进行中”。

### 4.3 完成任务

`multipart/form-data` 字段：

- `note`：可选，最多 500 字；
- `image`：可选，jpg/png/webp，最大 5MB；
- `longitude`、`latitude`：地点任务必传，不限地点任务可选。

后端不会相信前端计算出来的距离，而是用提交坐标和 `quest_record` 中的目标快照重新计算。超出半径返回：

```json
{
  "code": "LOCATION_TOO_FAR",
  "success": false,
  "message": "当前位置距离目标还有 860 米",
  "data": null
}
```

## 5. 主要错误码

| 错误码                        | HTTP | 含义                                     |
| ----------------------------- | ---- | ---------------------------------------- |
| `LOCATION_REQUIRED`           | 400  | 地点任务未提交坐标或动态任务未选择目标。 |
| `LOCATION_TOO_FAR`            | 409  | 完成位置超出允许半径。                   |
| `HIDDEN_QUEST_NOT_DISCOVERED` | 403  | 尚未解锁隐藏任务。                       |
| `HIDDEN_TOO_FAR`              | 403  | 距离隐藏任务解锁点太远。                 |
| `WEATHER_NOT_MATCHED`         | 409  | 当前天气不符合任务规则。                 |
| `MAP_PROVIDER_UNAVAILABLE`    | 503  | 天气限定任务所需的地图服务不可用。       |
| `ACTIVE_QUEST_EXISTS`         | 409  | 用户已有进行中的支线。                   |

## 6. 开发与生产数据库操作

开发环境 `synchronize=true`，启动 NestJS 后 TypeORM 会自动添加表和字段，并补充示例地图任务与本周主题。

生产环境 `synchronize=false`，应先备份数据库，再由 DBA 执行：

```bash
mysql -u 用户名 -p 数据库名 < database/migrations/20260814_v02_exploration.sql
```

该 SQL 是一次性升级脚本，不可重复执行。正式团队项目建议继续引入 TypeORM Migration 版本管理；当前学习项目保留 SQL 能更直接地看清每个实体字段如何映射到数据库。

## 7. 推荐联调顺序

1. 启动后端，确认 `/api/v1/themes/current`。
2. 传杭州坐标调用 `/api/v1/quests/nearby`，先验证固定任务。
3. 在高德控制台创建 Web 服务 Key，写入对应环境文件的 `AMAP_WEB_SERVICE_KEY`，再验证咖啡馆 POI。
4. 登录后测试收藏、取消收藏与发现隐藏任务。
5. 接取固定任务，分别用远距离和近距离坐标完成，观察 `LOCATION_TOO_FAR`。
6. 查询 `/api/v1/me/city-badges`，确认完成记录按城市汇总。
